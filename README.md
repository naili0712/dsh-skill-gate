# dsh-skill-gate

会话级技能门禁 + 加载审计 + 固定技能（含压缩兜底与历史恢复）。装完在会话顶部多一个「技能」tab。

## 能力

| 能力 | 说明 |
|---|---|
| 正文授权 | 手动模式下，模型读未放行的技能会被拦（`skill` 工具、`read` 直读、`pwsh`/`bash` 里的 cat 都拦） |
| 加载审计 | 记录模型真正读到了哪些技能、读了几次、用什么方式读的 |
| 固定技能 | 勾选后点「加载所选」，注入一次全文，后续工作按它执行 |
| 压缩兜底 | 压缩后自动降级注入要点摘要（最多 2 次），用尽后提醒手动重新注入 |
| 历史恢复 | 重启/重开后从会话历史恢复固定状态，面板不会与事实脱节 |
| 体积估算 | 每个技能显示字符数与 token 估算，固定的总量与占上下文百分比 |

## 两种模式

| 模式 | 行为 |
|---|---|
| **自动授权**（默认） | 模型自主读取，插件只记录，不拦 |
| **手动授权** | 未放行的技能读不到；模型请求时面板亮「待授权」，你点「放行」才生效 |

## 固定技能的生命周期

```
pin -> 注入一次全文
  | 压缩
自动注入要点摘要（第 1 次，几十~几百 token）
  | 压缩
自动注入要点摘要（第 2 次）
  | 压缩
注入警告 + 面板标红「正文已压缩·待重新注入」，停止自动恢复
  | 你点「重新注入」
再注入全文，自动计数归零
```

### 为什么要这样限流

注入全文 -> 超预算 -> 压缩 -> 检测到丢失 -> 再注入 -> 又超 -> 再压缩 会成死循环。所以自动路径只发摘要（小），全文必须点按钮。

## 重启后状态是怎么对上的

注入消息带 `source.kind = 'skill-gate'` 与技能名、内容 hash，跟着会话持久化。启动后第一次查面板时从 `snapshotEvents()` 恢复：

| 历史里找到 | 面板显示 |
|---|---|
| `pinned-full` + hash 一致 | 已固定（正文在上下文） |
| `pinned-full` + hash 不同 | 已固定 · 技能已更新·建议重新注入 |
| 只有 `pinned-summary` | 压缩后待补 |
| 只有 `stale-warning` | 正文已压缩·待重新注入 |
| 什么都没有 | 未固定（正常） |

面板顶部会显示「已从会话历史恢复 N 个固定技能」。

**恢复不出来的一种情况**：注入消息本身被压缩摘要掉了。那就退回「未固定」，这是正常降级，重新勾选即可。

## 体积估算

- 每行显示 `N tok`（鼠标悬停看字符数）
- 顶部显示已固定总量与占当前上下文百分比
- 算法是粗估：CJK 按 1 字 1 token，其他按 3.5 字符 1 token
- 上下文窗口取自会话的 `requestContext().contextWindow`，拿不到时百分比显示 0

## 技能组（office 套件）

office 那一套 7 个技能在面板上折叠成一组「Office 文档套件」：

- 组行显示：成员数、总 token、已固定数量
- 一键：**整组放行** / **整组固定** / **整组取消**
- 点 ▸ 展开可单独操作某个子技能

组定义在插件里（`BUILTIN_GROUPS`），匹配规则是 `name === 'office' || name.startsWith('office-')`，以后要加别的组改这一处即可。

> 内置 office 技能不在磁盘扫描根里，体积靠按 `path` 读文件补算（缓存 60 秒），所以以前显示 0 tok 的现在有数了。

### 自定义分组

勾选任意多个技能 → 点「新建分组」→ 填名字 → 创建。之后就是一组：

- 组行带「自定义」徽章，可展开、可**整组放行 / 整组固定 / 整组取消 / 删除组**
- 定义存在 `~/.dsh/skill-gate/groups.json`，跨会话共用
- 一个技能只归一个自定义组：新建时如果它已在别的组里，会自动从旧组摘出去
- 删除组只删定义，不影响已经固定的技能

自定义组优先于内置组：把 office 的技能拉进自己的组，它们就归你的组。

### 状态条与变更检测

面板第三行是一条加载状态条：

```
● 目录扫描于 15:44:02 · 2 个技能文件刚有变化：plugin-install-check、watch-video
  · 技能文件改动下一轮对话生效（无需重启）；插件自身更新需重启 DSH      [立即刷新]
```

- 目录扫描取**磁盘优先**：你在外面改了 SKILL.md，描述、token、体积下一轮刷新就会变
- 技能文件变了会用 mtime+size 比对，状态条标出来
- 已固定的技能如果文件被改过，那一行立刻变「技能已更新·建议重新注入」
- 点「立即刷新」强制重扫，不等 5 秒缓存

**生效规则**：技能文件改动不需要重启（DSH 每次加载都重读文件）；插件自身的代码更新需要重启 DSH。

### 展开状态会记住

组是展开还是折叠，存在浏览器 `localStorage`（键 `dsh-skill-gate:expanded`），关掉面板、切会话、重开都保持。隐私模式下存不了也不影响使用。

## 汉化

内置常用技能的中文名与简介。要改或补，写 `~/.dsh/skill-gate/labels.json`：

```json
{ "watch-video": { "label": "看视频", "summary": "场景检测切段 + 联系表" } }
```

## 已知限制

- 注入的消息以「user 消息」形式出现在对话里，视觉上像你发的（DSH 当前只有这种注入口）
- 压缩检测是粗粒度的：任何 `compaction/*` 事件都会把已固定技能标为「压缩后待补」，可能误报
- 未固定状态下，pin 需要会话工作目录就绪；刚开的空会话请先发一条消息再点「加载所选」
- 固定太多会吃上下文，建议同时 ≤2–3 个
- 门禁防的是"模型不知道规矩"，不是恶意绕过

## 安装 / 卸载 / 回滚

改 profile 的 `package.json`：dependencies 加 `"dsh-skill-gate": "link:<本仓库路径>"`，bundles 加 `"dsh-skill-gate"`，再在 node_modules 建 junction。改完必须完全退出并重启 DSH。

回滚：改动前先备份 profile 的 `package.json`，需要时还原。
